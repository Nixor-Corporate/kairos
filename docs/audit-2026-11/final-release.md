## Optional TA release and requeue proposal

Current Stop Serving closes the assigned session and permits a fresh student join. It handles the verified stale-session problem after the assignment-ID fix. Product should keep this existing flow by default. If staff-assisted recovery is needed, allow the assigned TA to release only their current assignment in their assigned course and room, with a separate explicit, student-confirmed choice to append to that queue's tail. Tail placement preserves the order of people already waiting. A student who left or whose readiness is unknown stays out of the queue and can rejoin through the current controls. Release displays that the session ended. A confirmed requeue displays the new waiting position after a committed REST refresh and sends one existing-style student hint.

Require the expected assignment ID, recheck authorization and student enrollment under the existing queue lock, atomically end the assignment and optionally insert one unique waiting row, and return the same outcome on retry. Reject stale requests against newer assignments. Record actor, course and queue, original assignment and student IDs, reason, timestamp, disposition and resulting position in durable audit data. Confirm existing audit storage can support the idempotency key, or add one narrow additive migration. Allow 3–5 engineering days including tests. Regressions to test include duplicate queue entries, lost positions, simultaneous accept/leave/rejoin, stale tabs, revoked access, duplicate hints and leaving while the confirmation is open. This is optional post-release work pending product approval.
