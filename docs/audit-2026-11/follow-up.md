## Approved feature review

- **Sign-off scope.** Course-wide toggles satisfy a uniform requirement for each new completion in the selected course. If requirements vary by task or category inside one course, the product owner must define precedence and historical reporting before that scope can change.
- **Explicit choice.** Each dialog starts with an empty rating, including a single-option scale and subsequent completions. Browser and client validation require a choice when configured, and the server verifies the supplied active option. The dialog identifies the selected student and task before saving. An idempotent retry of an already completed record preserves its original rating.
- **Workbook scope.** One download covers all in-scope rows for students currently enrolled in one managed course. Archived or withdrawn enrollment, deleted content, and a consolidated multi-course workbook require an explicit interpretation of “all student progress,” including access and retention rules. Existing attempt, submission, grade and progress fields retain the [documented dictionary](features.md).
- **Workbook capacity.** The 250,000-attempt run on local PHP/MariaDB took 20.48 seconds before transfer and reported 2 MiB of PHP allocator peak. Openpyxl counted every attempt. The 7,981,332-byte workbook contained 144,815,722 bytes of uncompressed worksheet XML. At staging, run the largest expected course with concurrent downloads. Record request and proxy timeouts, time to first byte and download completion, PHP worker/RSS usage, DB read-transaction time and private temp disk/quota. Verify cleanup after success, timeout and disconnect. Agree on capacity with hosting before release.
