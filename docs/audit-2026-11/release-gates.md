## SEC-05 · Canonical HTTPS

**Public downgrade fixed. Gate open for origin and authenticated browser verification.** Before the change, both HTTPS forms of `/signoff` returned `302 Location: http://kairos.nixorcorporate.com/`. HTTPS `/`, `/signoff/index.html` and `/signoff/api/config.php` returned `200`. Cloudflare Trace with origin forwarding confirmed the two `302` responses without a matching redirect rule. The zone used Full SSL, Always Use HTTPS off, HSTS off and WebSockets on. There was no applicable Page Rule, Worker route, Origin Rule or Bulk Redirect. The locally managed Kairos Tunnel had one connector, routing `/websocket/*` to a local HTTP relay and all other Kairos paths to the HTTP application origin with the canonical Host header. The fault is on the application origin path. The specific cPanel redirect, vhost rule, or deployed `.htaccess` requires host access. [Cloudflare Tunnel local configuration](https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/configuration-file/)

Two active, reversible Cloudflare rules apply only to `GET` and `HEAD` on the Kairos hostname and the exact sign-off entrypoints. Rule `e893f94052854d938c2682c6d3326f46` (`kairos_signoff_https_entrypoint`) internally rewrites HTTPS `/signoff/` to the verified `/signoff/index.html` handler. Rule `7a8b1444880143618b388dfb6b3519f7` (`kairos_signoff_canonical_https`) redirects HTTP `/signoff` and `/signoff/` and HTTPS `/signoff` to HTTPS `/signoff/`, preserving the query. The previous redirect rule and zone TLS settings were retained. Cloudflare Trace matched the two new rules only on their intended paths and returned no match for the OAuth API path or a sibling host. Roll back by disabling the added redirect first, then the added rewrite. [URL rewrite behavior](https://developers.cloudflare.com/rules/transform/url-rewrite/create-api/)

Public verification showed HTTP and slashless variants reach HTTPS `/signoff/` in one hop for GET and HEAD. The canonical route and its query probe returned `200`. The dashboard script and configuration API responded over HTTPS. The anonymous session cookie was `Secure`, `HttpOnly`, `SameSite=Lax`, path `/`. The Google Identity POST endpoint accepted the anonymous session and matching CSRF token over HTTPS, then correctly returned `400 missing_credential` for the empty credential request. The public Socket.IO WSS upgrade returned `101`. Successful institutional Google credential exchange, authenticated cookie reuse after reload and logout, and authenticated hosted Socket.IO event delivery require a test account and a staged release. [Public canonical URL](https://kairos.nixorcorporate.com/signoff/)

1. On the machine running `cloudflared`, use `cloudflared tunnel ingress rule https://kairos.nixorcorporate.com/signoff/` and review the matched application's local origin service. From that host, send GET and HEAD to the configured origin with `Host: kairos.nixorcorporate.com` and `X-Forwarded-Proto: https`, for `/signoff`, `/signoff/`, `/signoff/index.html` and `/signoff/api/config.php`. Compare status and Location with a direct request omitting the forwarded scheme header. If the origin offers TLS, test its certificate and vhost with `curl --resolve` and canonical SNI. Keep private addresses in the operator record.
2. In cPanel **Domains** confirm the document root. Check **Redirects**, the Kairos vhost and both root and mounted `.htaccess` files for `/signoff/?` to `/`, hard-coded `http://`, and generated redirects using the internal HTTP scheme. Delete or correct the confirmed offending rule in the Kairos vhost only. Make `/signoff/` internally route to the verified index handler and make `/signoff` redirect explicitly to `https://kairos.nixorcorporate.com/signoff/`. Preserve queries. Trust forwarded scheme only from the configured proxy and verify loop safety before any vhost HTTPS enforcement. [cPanel Redirects](https://docs.cpanel.net/cpanel/domains/redirects/)
3. Verify the origin directly before retiring the temporary rewrite. Stage with `APP_ORIGIN` and `PUBLIC_APP_ORIGIN` set to the HTTPS host, `APP_BASE_PATH=/signoff/`, secure session cookies and `WS_PUBLIC_URL=wss://kairos.nixorcorporate.com`. Run institutional Google sign-in through the existing credential POST, then local sign-in, protected route reload, authenticated WSS and logout. Capture only statuses, cookie attributes and event outcomes.

## SEC-06 / SEC-07 · WebSocket authorization and host isolation

**Code remediated locally. Hosting gate open.** Previously a signed query-string token could outlive logout and a connected socket kept its memberships after access changes. The updated PHP issue path uses an opaque per-login lease with a stored digest, expiry and account session version. Logout revokes that login's lease. The relay accepts the token in the Socket.IO auth frame, validates the exact browser origin, and checks current DB identity and course/room authorization immediately before each protected delivery. Queue alerts target the current student, projector events require scoped staff access, and student-specific LMS events respect recipient scope. A stale connection cannot receive further protected deliveries. Idle connections are evaluated on the next applicable delivery or reconnect. REST remains authoritative.

The broker requires a loopback peer and its own environment secret. Apache denies public emit aliases in the reviewed configuration, the local emitter rejects redirects and proxies, and socket packet logging is disabled. The public service returned `405` on `GET /emit` and `/signoff/emit` before any app deployment, confirming a hosted broker route still needs attention. Default direct emitter destination is `http://127.0.0.1:8090/emit`. Neither a host shell nor a staged authorized user session was available for runtime verification.

The local security commit is `183a9bed14aae1ab580c92718b8c83e23135c586`. The PHP/Node suite passed 44 tests with one credential-gated Drive skip. The Python integration passed with PHP 8.4.27, MariaDB 10.11.19 and live loopback Socket.IO event delivery through the actual emitter. Migration `0500` applied twice without error.

Local regression entrypoints are `node tools/tests/realtime_runtime_test.mjs` and `python tools/tests/realtime_authorization_test.py`. For the Python test create a disposable loopback database named `kairos_realtime_test` from the base schema, discovery, local auth and `0500` migrations and `tools/tests/fixtures/queue_enrollment.sql`. Use the fixture's synthetic Argon2id password setup. Run PHP and Python with the same DB, `WS_SHARED_SECRET`, exact loopback `WS_ALLOWED_ORIGINS`, and a loopback `WS_PUBLIC_URL`. Set `KAIROS_TEST_PORT` and `KAIROS_TEST_PASSWORD`. For a real socket and broker smoke also run the relay with `boot.py` on a separate loopback port and set `KAIROS_TEST_RELAY_PORT`. This test changes the synthetic accounts and grants. Keep the DB isolated.

1. Apply `db/migrations/20261116_0500_add_realtime_session_leases.sql` after the local-auth schema. Stage the matching PHP, JS, relay, emitter, and Apache configuration together. `WS_ALLOWED_ORIGINS` should contain the exact HTTPS Kairos origin. Set `WS_DB_USERNAME` and `WS_DB_PASSWORD` in the relay service environment for a distinct least-privilege DB identity. Grant only reads of the lease, user authorization fields, roles, active courses, rooms and installed course grant tables, plus read of the needed outbox fields and update of `delivered_at` if enabled. The PHP account needs lease read/insert/delete. Keep environment and session files outside the webroot and readable only by their service identities. Ensure outbox processing is compatible with the worker topology.
2. On the connector/app host, inspect `ss -ltnp` and service configuration. Verify that the relay port is loopback-only, the tunnel forwards the Socket.IO path, and the vhost has no public `ProxyPass`, rewrite, or alias that forwards to `/emit`. Verify the expected service UIDs and file permissions without printing process environments. Confirm that public GETs to `/emit`, `/signoff/emit` and `/websocket/emit` return `403` or `404`. Smoke one staging event through the real PHP worker and local emitter. Record only success, destination class and timing.

Withdraw course access, remove staff access, disable an account, rotate a session version, log out one of two sessions, and expire a lease. Check that no subsequent protected events arrive and that expired or revoked leases and course scopes are denied on reconnect. Check that the unaffected session and legitimate target still receive events. Verify that access logs and packet logs omit bearer values and that queue and LMS notices still work through authenticated WSS. Record staged latency and DB load for representative simultaneous subscriptions.
